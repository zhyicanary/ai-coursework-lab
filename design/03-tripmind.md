## 一、项目概述

### 1.1 项目名称
**TripMind** — 基于多智能体协同的智能旅游助手

### 1.2 一句话描述
用户输入目的地、天数、预算，多个 AI Agent 自动分工协作（查交通、比住宿、排行程、看天气、算预算），实时展示 Agent 协作过程，最终生成完整旅行方案。

### 1.3 双重用途

| 用途 | 侧重点 | 提交物 |
|------|--------|--------|
| **项目二** | 展示多 Agent 协同 + LangGraph + MCP 技术 | 源码 + 文档 + 视频 |
| **竞赛** | 展示垂直场景落地 + 实用价值 | 源码 + 演示 |

### 1.4 与项目一的差异化

| 维度 | 项目一 KnowSeeker | 项目二 TripMind |
|------|-----------------|-----------------|
| Agent 数量 | 1 个（多步推理） | 5 个（协同分工） |
| 核心机制 | Agentic RAG 检索链 | Multi-Agent 任务编排 |
| 用户场景 | 上传文档 → 问答 | 输入需求 → Agent 协作规划 |
| 输出形式 | 带引用的答案 | 完整旅行方案 |
| 前端 | Streamlit | Gradio |
| 课程侧重 | RAG + MCP | Multi-Agent + LangGraph + MCP |

### 2.2 功能需求（用例）

```
UC-01  提交旅行需求
       └─ 用户输入：目的地 + 天数 + 预算 + 偏好
       └─ 例："成都 3天 3000元 喜欢美食和历史文化"

UC-02  自动任务分解
       └─ Orchestrator 自动拆解为子任务
       └─ 生成 DAG 依赖图
       └─ 展示分解结果

UC-03  Multi-Agent 协同执行
       └─ 天气 Agent（无依赖，直接查）
       └─ 交通 Agent（无依赖，查航班/高铁）
       └─ 住宿 Agent（查酒店，参考预算）
       └─ 行程 Agent（依赖：天气 + 交通到达时间）
       └─ 预算 Agent（依赖：交通 + 住宿 + 行程）
       └─ 汇总 Agent（依赖：所有 Agent 完成）

UC-04  方案展示
       └─ 完整旅行方案（行程表 + 费用明细 + 天气提醒）
       └─ 各 Agent 贡献标注

UC-05  追问调整
       └─ "换个便宜点的酒店" → 住宿 Agent 重新搜索
       └─ "多玩一天" → 行程 Agent + 预算 Agent 重新规划
       └─ 仅重算受影响的 Agent
```

### 2.3 非功能需求

| 需求 | 指标 |
|------|------|
| 响应时间 | 完整规划 < 40 秒 |
| Agent 数量 | 5 个专业 Agent + 1 个调度 Agent |
| 可视化 | 实时展示每个 Agent 执行状态 |
| 容错 | 单个 Agent 失败不阻塞（如天气 API 不可用，标注"暂无天气数据"） |

### 3.3 核心数据结构

```python
class TravelRequest(TypedDict):
    """用户旅行需求"""
    destination: str          # 目的地
    days: int                 # 天数
    budget: float             # 预算（元）
    preferences: list[str]    # 偏好 ["美食", "历史文化"]
    departure_city: str       # 出发城市

class SubTask(TypedDict):
    id: str
    agent: str                # "transport" | "hotel" | "weather" | "itinerary" | "budget" | "summarizer"
    description: str
    dependencies: list[str]   # 依赖的子任务 ID
    status: str               # "pending" | "running" | "done" | "failed"

class TravelState(TypedDict):
    """Multi-Agent 协作全局状态"""
    request: TravelRequest
    sub_tasks: list[SubTask]
    weather_result: dict | None     # 天气 Agent 结果
    transport_result: dict | None   # 交通 Agent 结果
    hotel_result: dict | None       # 住宿 Agent 结果
    itinerary_result: dict | None   # 行程 Agent 结果
    budget_result: dict | None      # 预算 Agent 结果
    final_plan: str | None          # 汇总 Agent 最终方案
    agent_logs: list[dict]          # Agent 执行日志（前端展示用）
```

### 4.4 LangGraph 核心编排逻辑

```python
def build_travel_graph() -> StateGraph:
    """构建旅游助手 LangGraph 状态机"""

    workflow = StateGraph(TravelState)

    # 添加节点
    workflow.add_node("orchestrator", orchestrator_node)   # 调度
    workflow.add_node("transport", transport_agent)         # 交通
    workflow.add_node("hotel", hotel_agent)                 # 住宿
    workflow.add_node("weather", weather_agent)             # 天气
    workflow.add_node("itinerary", itinerary_agent)         # 行程
    workflow.add_node("budget", budget_agent)               # 预算
    workflow.add_node("summarizer", summarizer_agent)       # 汇总

    # 编排边
    workflow.add_edge(START, "orchestrator")
    workflow.add_conditional_edges("orchestrator", dispatch_to_agents, {
        "transport": "transport",
        "hotel": "hotel",
        "weather": "weather",
        "itinerary": "itinerary",
        "budget": "budget",
        "summarizer": "summarizer",
        END: END,
    })
    workflow.add_edge("transport", "orchestrator")    # 完成后回到调度器
    workflow.add_edge("hotel", "orchestrator")
    workflow.add_edge("weather", "orchestrator")
    workflow.add_edge("itinerary", "orchestrator")
    workflow.add_edge("budget", "orchestrator")
    workflow.add_edge("summarizer", END)

    return workflow.compile()
```

  ▼

## 七、课程要求覆盖检查

| 课程关键词 | TripMind 覆盖方式 |
|-----------|------------------|
| ✅ 大模型 | DeepSeek API 驱动所有 Agent |
| ✅ AI Agent | 6 个独立角色 Agent（1调度+5专业） |
| ✅ LangChain | Agent 工具封装、景点 RAG 检索链 |
| ✅ LangGraph | Multi-Agent DAG 编排 + 状态机 |
| ✅ MCP | 自建 MCP Server，暴露航班/酒店/天气/景点 Tool |
| ✅ RAG | 景点/攻略知识库向量检索（ChromaDB） |
| ✅ 多智能体协同 | **核心卖点**：DAG 依赖调度、并行执行、消息通信 |

## 八、数据来源策略

考虑到项目不需要真实 API：

| 数据 | 方案 | 
|------|------|
| 航班/高铁 | 预置模拟数据（京→蓉、沪→蓉等热门线路），LLM 根据常识补充 |
| 酒店 | 预置模拟数据 + LLM 常识生成 |
| 天气 | 优先用免费 API（和风天气/OpenWeather），不可用时用 LLM 模拟 |
| 景点 | 预置景点知识库（ChromaDB 向量化），手写 10-20 个热门城市景点数据 |

> **答辩话术**："当前演示使用模拟数据，实际生产环境中可接入真实 API，MCP 协议的标准化接口使得替换数据源只需修改 Server 端，Agent 端代码无需任何改动。"
